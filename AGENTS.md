# GoldenPixel

> Built with Arc Studio - money-powered apps in minutes

This is the **project memory** - what Arc Studio remembers about building this app. It helps future agents (or humans) understand and extend the project.

## What This App Does

GoldenPixel is a client-side image toolkit (editor, collage maker, compressor, converter) with a black-and-gold cosmic design. No wallet or onchain features. Design tokens (CSS variables `--gp-*`) and component classes (`gp-card`, `gp-btn`, `gp-seg`, `gp-drop`) live in `src/index.css`; routing is a small path router in `src/lib/router.tsx`; pages are in `src/pages/`.

## Tech Stack

- Frontend: React 18, Vite, TypeScript, Tailwind CSS
- Web3: wagmi v2, viem v2, ConnectKit
- Contracts: Solidity 0.8.28 + Foundry. Sources in `contracts/`, unit tests in `contracts/test/*.t.sol`. Build with `bun run contracts:build` (`forge build`), test with `bun run contracts:test` (`forge test`).
- Wallet: injected (MetaMask, etc.)
- Chain: Arc Testnet (Chain ID: 5042002, imported from `viem/chains`)
- Token: USDC (6 decimals) (Address: 0x3600000000000000000000000000000000000000, Chain: Arc Testnet)
- Toasts: Sonner

## Key Files

- `src/App.tsx` - Main application logic
- `src/components/` - UI components
- `src/config.ts` - wagmi config (chains, connectors, transports)

## Web3 and payments notes

- Wallet: wagmi injected connector; chains in `src/config/bridgeChains.ts` (testnets only). `src/components/wallet/WalletButton.tsx`.
- Swap and Bridge: Circle App Kit (`@circle-fin/app-kit` 1.18) with the viem browser-wallet adapter, keyless. No KIT_KEY or server is needed for swaps in the current SDK; never put an API key in the browser. Swap on Arc supports USDC, EURC and cirBTC only; the UI offers USDC and EURC.
- Payments: `src/config/payments.ts` (recipient, packs, credit costs) and `src/config/networks.ts` (network, official USDC pin). Server in `server/` verifies the USDC transfer onchain, credits the paying wallet once per `chainId:txHash`, and spends credits only against a wallet signature. Active network: Arc Testnet. Mainnet is NOT enabled; it needs explicit user confirmation of the mainnet warning first.
- Recipient: 0xd7d80191dee0a4cd481766b82b0c38c7feb63586 (user supplied). Never use the shared deployer wallet.
- Demo credits are local only (localStorage) and are labeled; they never count as payment.
- Premium processing runs in the browser, so credit gating is a ledger/UX control, not DRM. Move processing server-side to enforce it strictly.

## Localization (EN/VI)

- Custom i18n in `src/i18n/` (no dependency). English default; choice persists in localStorage `gp-lang`. `vi.ts` is typed against `en.ts`.
- Components use `useI18n()` (`t`, `td`, `m`, `fmt`). Messages kept in state are `Msg` ({key, vars}) so they re-render in the active language; never store translated strings in state.
- `parseOnchainError` returns a `Msg`. Server rejection codes map to `pay.reject.*`. Provider/SDK detail text stays as the provider wrote it, under a translated lead-in.
- The wallet signature message for spending credits is generated by the server in English (it is the signed payload); the Arc Studio watermark in `main.tsx` is platform UI and is not translated.
- `bun run test` checks key parity, placeholder parity and dead/missing keys.

## Free vs premium architecture

- Limits: `src/config/plans.ts`. Prices and the operations table: `src/config/payments.ts` (the server prices every request from it).
- Flow for any premium output: `usePremiumAction().run(ops, produce)` = reserve (server verifies the wallet signature and takes credits) -> produce -> commit; on failure, release (refund). Unsettled holds are refunded by the server after 10 minutes. Free paths never call it and never need a wallet.
- Free limits are checked in the browser (`loadWithLimits`). Valid files over the limit are held, not discarded, and loaded after a Pro batch is unlocked.
- All processing is local. Files are validated by real type (magic bytes), size and pixel count; canvases are released after export; object URLs are revoked on removal and unmount.
- Known limitation: output is generated client-side, so entitlement is a ledger/UX control, not DRM. Moving a premium operation server-side requires an image library and upload handling (limits, cleanup, privacy notice).

## File Converter module

- Engines in `src/lib/convert/`: ZIP reader (DecompressionStream), DOCX and XLSX reader/writer (regex over OOXML, no dependency), CSV, `pdfTools` (pdf-lib), `pdfRender` (pdf.js, lazy; assets in `public/pdfjs`), `docxPdf` (Noto Sans woff in `public/fonts`), `runners` (one function per conversion, environment injected so tests can run them in Bun).
- UI: `src/pages/Convert.tsx` (hub, route `/convert/<tool>`), `components/convert/Workspace.tsx` (generic: validate, limits, progress, results, ZIP, credits), `tools.tsx` (per-tool options), `PdfOrganizer.tsx`, `ImageConverter.tsx`. Catalog in `lib/convert/catalog.ts` marks tools ready / basic / unsupported.
- Premium runs use `usePremiumAction().run` (reserve, produce, commit; any throw refunds). A run with zero outputs throws so credits are never kept for a failure.
- Development credits are a separate balance (`gp-dev-credits`, source switch `gp-credit-source`), only active when `DEV_ALLOWED`. Holds from them are prefixed `dev-` and never reach the server.
- Unsupported on purpose (need a server engine): PPTX to PDF, legacy .doc/.xls/.ppt. Do not add fake converters.
- PDF to Word is browser-only: `pdfExtract.ts` (pdf.js text, images, rotation) -> `pdfLayout.ts` (pure layout analysis: columns, tables, paragraphs, headings, lists) -> `docxBuild.ts` (docx library, lazy). OCR (`ocr.ts`, tesseract.js) is opt-in and lazy; a scanned PDF without OCR is refused, never converted to an empty file.
- Browser E2E for this module was run with Playwright against real sample files made by independent libraries (docx, exceljs, pdfkit); see the report in the conversation, not in the repo.

## Direct USDC payments (current design)

- Frontend only: no backend, no database, no credits. Do not re-add them without being asked.
- Config: `src/config/payments.ts` (recipient, per-feature `priceUsdc`), `src/config/networks.ts` (network + pinned official Arc USDC). Arc Mainnet is NOT enabled until the user confirms the mainnet warning; the registry lists testnet only.
- `src/lib/payments/verify.ts` checks a transaction from chain data only (chain, token, sender, recipient, exact amount, receipt, confirmations, Transfer event from the USDC contract, mined after Pay). `flow.ts` polls and records; `session.ts` keeps hashes in sessionStorage; a stored record unlocks only after `revalidate.ts` re-verifies it on-chain in the current page load.
- `usePremiumAction()` is the one hook tools use: `run(features, produce)` / `ensurePaid(features)` / `isUnlocked` / `priceOf`. `PaymentSheet` is the only place a payment starts. There is no manual tx-hash entry and no simulated payment path. Do not add either.
- It is a convenience gate, not enforcement. Never describe it as fraud-proof.

- Audio to Text: `src/lib/audio` (models, segmenting, decode, worker, client) + `components/convert/AudioToText.tsx`. Real Whisper inference only; never add placeholder transcripts or a cloud fallback. `vite.config.ts` points onnxruntime's wasm at the jsDelivr CDN to keep dist small: do not remove that plugin or dist grows by ~27 MB. Free up to 5 min, `audio-long` (0.20 USDC, session unlock) up to 30 min.

- Meteor shower: `src/lib/meteors.ts` (model + painter, unit-tested) and `components/MeteorShower.tsx` (canvas loop). Meteors always enter from the right/top-right and travel left-down at 30-40 degrees with the head leading; do not reintroduce the old CSS `gp-shooting` streaks. ClearFund source was not available in this workspace, so the effect was designed independently.
